## 1. 프로젝트 소개

### 1.1 프로젝트 정의

운동 부위를 고르면 맞는 헬스 기구를 추천하고, 기구 사용법을 안내하는 모바일 웹 서비스이다.

### 1.2 프로젝트 목표

- 운동 부위 선택 (가슴 · 등 · 어깨 · 하체 · 팔 · 유산소)
- 부위에 맞는 기구 추천
- 기구별 타깃 근육, 운동 목적, 사용법, 주의사항 안내
- 규칙 기반 추천과 직접 학습한 AI 모델의 결과 비교
- 추천 기구를 요일별 계획표에 담기
- 회원가입 및 로그인 기능 제공
- 다른 사용자의 계획표를 보고 좋아요 · 저장 (스케줄 공유)
- 회원 데이터 · 마이 데이터를 데이터베이스에 저장

**최종 목표:** 초보자가 운동 부위에 맞는 기구와 기본 사용법을 쉽게 확인하게 한다.

### 1.3 AI와 사람의 역할

| 구분 | 역할 |
| --- | --- |
| AI 모델 | 운동 부위에 맞는 기구 추천 (아직 구현 안 함) |
| 프로그램 (화면) | 기구 정보 표시, 계획표 · 공유 화면 |
| 프로그램 (서버) | 회원 · 계획표 · 공유 · 좋아요 저장, 입력값 검사, 비밀번호 해시 |
| 데이터베이스 (Supabase) | 회원 데이터 · 마이 데이터 · 기본 데이터 보관 |
| 사람 | 기구 정보와 번역 검수, Supabase 설정 · 키 관리, 사용자 테스트 |
| Claude | 화면 설계 · 코드 작성, 기구 설명 번역 지원 |

**검증할 목표:** 부위별 기구 추천과 사용법 안내가 초보자에게 도움이 되는지 확인한다. 아직 검증된 결과는 아니다.

## 2. 사용자·문제·가치

### 2.1 목표 사용자

헬스 기구 사용법을 잘 모르는 초보자

- 7주차 기획서: 헬스장에 처음 등록한 20대 초보 운동자, 기구 사용법을 혼자 공부하는 대학생

### 2.2 해결하려는 문제

운동 부위에 맞는 기구를 고르기 어렵다. 기구 사용법을 찾기도 어렵다.

사용법과 자세를 모르면 다칠 수 있다. 유튜브 · 블로그 · SNS 정보는 품질과 신뢰도가 제각각이다.

### 2.3 제공할 가치

1. **기구 추천:** 고른 부위에 맞는 기구 확인
2. **사용법 안내:** 시작 자세, 동작, 주의할 점 확인
3. **계획 관리:** 기구를 요일별 계획표에 담고 완료 체크
4. **계획 공유:** 다른 사람의 계획표를 참고하고 내 계획표로 저장

### 2.4 확인한 사실과 가설

| 구분 | 내용 |
| --- | --- |
| [사실] | 위 사용자 · 문제 · 가치는 팀이 정한 기획 방향이다. |
| [사실] | 7주차 기획서의 시장 근거: 국민 생활체육 참여율 62.9%, 보디빌딩 선호도 17.5%, '플랜핏' 누적 이용자 400만 명 |
| [사실] | 기획서는 부상 원인으로 무리한 중량과 잘못된 자세를 들었다. |
| [가설] | 실제 초보자도 기구 선택과 사용법에서 불편을 겪는다. |
| [가설] | 부위별 추천과 사용법 안내가 초보자에게 도움이 된다. |
| [가설] | 초보자가 계획표와 스케줄 공유를 쓰고 싶어 한다. |
| [가설] | 한국어로 옮긴 기구 설명을 초보자가 쉽게 이해한다. |

## 3. 만들 범위

### 3.1 개발 계획

| 항목 | 내용 |
| --- | --- |
| 운동 부위 | 6개 (가슴 · 등 · 어깨 · 하체 · 팔 · 유산소) |
| 기구 데이터 | 18종 (부위별 3개, 예시 데이터) |
| 공유 계획표 예시 | 4개 (예시 사용자) |
| 추천 방식 | 규칙 기반 추천, 학습 모델 (둘 다 아직 구현 안 함) |
| 현재 추천 결과 | 고정 예시 데이터 |
| 데이터 출처 | free-exercise-db (퍼블릭 도메인), 영문 설명을 한국어로 번역 |
| 화면 | HTML, CSS, JavaScript |
| 서버 | Python, Flask |
| 데이터베이스 | Supabase (무료 플랜) / 예비: 서버 JSON 파일 |
| 모델 | Python, pandas, scikit-learn (아직 구현 안 함) |

*규칙 기반 추천: 정해 둔 규칙(부위 ↔ 근육)으로 기구를 고르는 방법*

*학습 모델: 데이터를 학습해서 기구를 고르는 AI 모델*

### 3.2 Must Have — 반드시 필요한 기능

1. 운동 부위 선택
2. AI 기구 추천 (결과가 없으면 안내 메시지)
3. 기구별 타깃 근육 및 운동 목적 안내
4. 기구 사용법 및 주의사항, 참고 출처 안내
5. 모델 성능 평가 (테스트 데이터 평가 결과, 오추천 사례)

**프로토타입 상태** [사실]

- 1, 3번은 구현했다.
- 2번은 화면만 있다. 결과는 고정 예시 데이터다.
- 4번은 시작 자세 · 동작 · 주의할 점을 보여 준다. 기구별 출처 표시는 없다.
- 5번은 아직 없다.

### 3.3 Should Have — 추가하면 좋은 기능

1. 운동 부위 변경 및 재추천

**프로토타입 상태** [사실] '다른 부위 보기' 버튼과 '부위별 추천' 탭으로 구현했다.

### 3.4 Could Have — 프로토타입에서 생긴 기능

1. 요일별 계획표 (마이페이지 안)
2. 회원가입 · 로그인 · 로그아웃 · 회원 탈퇴
3. 스케줄 공유 (보기 · 좋아요 · 내 계획표에 저장 · 내 계획표 공개)
4. 홈 화면 인기 스케줄 (좋아요 1위)

**로그인 기능** [사실: 프로토타입 동작]

- 이름, 이메일, 비밀번호로 회원가입
- 이메일과 비밀번호로 로그인
- 잘못된 입력은 입력칸마다 안내 (브라우저와 서버에서 두 번 검사)
- 잘못된 비밀번호는 오류 안내
- 비밀번호는 서버에서 해시로 바꿔 저장
- 새로고침하거나 다른 기기에서 로그인해도 같은 계정 · 계획표 사용
- 회원 정보는 Supabase `users` 테이블에 저장

### 3.5 제외할 기능

- 기구 사진 인식
- 생성형 AI 대화형 상담

## 4. 화면 구성 및 사용 순서

### 4.1 화면 구성

| 화면 | 주요 기능 |
| --- | --- |
| 홈 | 서비스 소개, '운동 부위 고르기', 인기 스케줄, 이용 순서 |
| 운동 부위 선택 | 6개 부위 중 하나 선택 |
| AI 추천 결과 | 기구 3개, '예시 데이터' 표시, 사용법 펼쳐 보기, 계획표에 추가 |
| 부위별 추천 | 부위를 누르면 바로 추천 결과 |
| 스케줄 공유 | 공유 계획표 목록 (인기순 · 최신순), 상세, 좋아요, 저장 |
| 로그인 · 회원가입 | 계정 생성, 로그인 |
| 마이페이지 | 프로필, 통계, 내 계획표, 공유 설정, 로그아웃, 탈퇴 |

- 하단 탭: 홈 / 부위별 추천 / 스케줄 공유 / 마이페이지
- 화면 ID: 팀 결정 필요

### 4.2 사용자 사용 순서

1. 홈에서 '운동 부위 고르기'를 누른다.
2. 운동 부위를 하나 고른다.
3. 'AI 기구 추천받기'를 누른다.
4. 추천 기구를 확인하고 사용법을 펼쳐 본다.
5. 기구를 요일별 계획표에 담는다.
6. 로그인하고 마이페이지에서 계획표를 관리한다.
7. 스케줄 공유에서 다른 사람의 계획표를 보고 저장한다.

### 4.3 예외 상황 [사실: 프로토타입 동작]

| 상황 | 화면 반응 |
| --- | --- |
| 부위를 고르지 않고 추천을 누름 | 경고 문구 표시 |
| 로그인 없이 좋아요 · 저장을 누름 | 로그인 화면으로 이동 |
| 같은 요일에 같은 기구를 또 추가 | "이미 계획표에 있어요" 안내 |
| 데이터 파일을 못 불러옴 | 실행 방법 안내 화면 |
| 서버가 꺼져 있음 (Live Server 등으로 실행) | 로그인 · 회원가입 화면에 서버 실행 방법 안내 |
| 데이터베이스(Supabase)에 연결 안 됨 | 로그인 · 저장 시 "데이터 저장소에 연결하지 못했어요" 안내, 기구 · 예시 데이터는 `data/` 파일로 표시 |

| 기능 | 완료 기준 |
| --- | --- |
| 부위 선택 | 6개 부위 중 하나를 고를 수 있다. |
| 기구 추천 | 고른 부위에 맞는 기구가 나온다. |
| 기구 정보 | 타깃 근육과 운동 목적이 보인다. |
| 사용법 안내 | 시작 자세, 동작, 주의할 점, 출처를 볼 수 있다. |
| 모델 성능 평가 | 테스트 데이터 평가 결과와 오추천 사례를 볼 수 있다. |
| 부위 변경 | 다른 부위로 바꿔 다시 추천받을 수 있다. |
| 계획표 | 요일 · 세트 · 횟수를 정해 담고, 완료 체크 · 삭제를 할 수 있다. |
| 로그인 | 회원가입 · 로그인 · 로그아웃이 작동한다. |
| 스케줄 공유 | 좋아요, 내 계획표에 저장, 내 계획표 공개가 작동한다. |
| 데이터 저장 | 회원 · 계획표 · 공유 설정 · 좋아요가 데이터베이스에 저장된다. |

### 5.1 기록할 데이터와 저장 위치

| 데이터 | 내용 | Supabase 테이블 | 예비 (JSON 방식) |
| --- | --- | --- | --- |
| 회원 데이터 | 이름, 이메일, 해시로 바꾼 비밀번호, 가입일 | `users` | `db/users.json` |
| 마이 데이터 | 요일별 계획표 (기구 id, 세트, 횟수, 완료 여부) | `plans` | `db/plans.json` |
| 공유 설정 | 공개 여부, 제목, 소개 | `share_settings` | `db/share_settings.json` |
| 좋아요 | 계획표 id, 누른 회원 | `likes` | `db/likes.json` |
| 기구 데이터 | 기구 id, 이름, 부위, 주요 근육, 운동 목적, 난이도, 시작 자세, 동작, 주의할 점, 사진 경로 | `exercises` | `data/exercises.json` |
| 공유 예시 | 예시 계획표 4개 | `shared_samples` | `data/shared_plans.json` |
| 비회원 계획표 | 로그인 전에 담은 기구 | — (브라우저에 임시 저장, 로그인하면 옮김) | — |

- 저장 방식은 서버 설정 파일(`.env`)의 `STORAGE_MODE`로 고른다. (`supabase` / `json`)
- **모델 평가 데이터:** 팀 결정 필요

### 5.2 성능 평가 지표

PRD 0.1에서 정한 지표: Precision@K, Recall@K 등

*Precision@K: 추천한 K개 중 맞는 기구의 비율*

*Recall@K: 맞는 기구 전체 중 추천 K개 안에 들어간 비율*

- K 값과 정답 기준: **K = 3**, 정답 기준 = 팀원이 출처를 보고 직접 매긴 "부위별 정답 기구 목록"

### 5.3 API 연동 · 보안

| 항목 | 내용 |
| --- | --- |
| 연동 대상 | Supabase REST API |
| 사용하는 키 | secret 키 (`sb_secret_`) — 서버 `.env`에만 저장 |
| 키 보호 | `.env`는 GitHub에 올리지 않는다 (`.gitignore`). 브라우저에는 키를 보내지 않는다. |
| 테이블 보안 | 모든 테이블에 RLS를 켠다. 브라우저용 키로는 읽기 · 쓰기가 안 된다. |
| 비밀번호 | 서버에서 해시로 바꿔 저장한다. |
| 공유 목록 | 회원 이메일 대신 바꾼 id(`user-xxxx`)를 보여 준다. |
| 키 유출 시 | Supabase에서 그 키를 삭제하고 새로 발급한 뒤 팀원 `.env`를 바꾼다. |

- 다른 외부 API(운동 정보 API, 생성형 AI 등)는 연동하지 않는다. 생성형 AI 대화형 상담은 3.5의 제외 기능이다.

## 6. 테스트 방법 및 성공 기준

### 6.1 테스트 방법

| 테스트 | 확인할 내용 | 진행 상태 |

## PRD 0.3 최종 요약

**머신메이트**는 운동 부위를 고르면 맞는 헬스 기구를 추천하고, 사용법과 주의사항을 안내하는 모바일 웹 서비스이다.

사용자는 추천받은 기구를 요일별 계획표에 담고, 마이페이지에서 관리한다. 스케줄 공유에서는 다른 사람의 계획표에 좋아요를 누르고 내 계획표로 저장할 수 있다.

PRD 0.3에서 데이터 저장 위치를 **Supabase 데이터베이스**로 정했다. Flask 서버가 Supabase REST API로 데이터를 저장하고, API 키는 서버에서만 관리한다.

지금 추천 결과는 고정 예시 데이터이다. 규칙 기반 추천과 학습 모델의 비교는 아직 하지 않았다.

**최종 기능 우선순위**

- Must Have: 5개
- Should Have: 1개
- Could Have: 4개
- 제외: 2개
